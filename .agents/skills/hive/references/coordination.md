# Coordinate Beads work

## Claim and hand off

Inspect current assignment and blockers immediately before claiming through `br update --help`. Record the scope and execution checkout: sessions can share an actor, so a matching identity alone does not prove that no other session is working there.

When delegating, follow `bee skills get delegation` for submission, retained IDs and result delivery. Choose bee kinds from repository policy and available configuration.

## Keep resumable evidence

Append progress, decisions, verification and handoff context to task notes. For Busy Bee stages, put narrative evidence in comments and reserve notes for the original workflow outcome. Inspect saved progress after interruption before repeating effects.

Leave unfinished work open with the blocker and next action. Close a parent only after its children and overall acceptance are satisfied.

## Dots publication policy

Read tracker state through `br` or BV. `br` generates `.beads/issues.jsonl` in the permanent tracker; do not parse or edit that export manually. Application commits neither flush nor stage it.

Setup and `beeswax sync` stay local. Run `beeswax beads sync` only at an authorized tracker publication checkpoint; ordinary task updates and worker handoffs stay local. At that checkpoint, follow `beeswax skills file repository-setup references/publication.md` for exchange and recovery. Tracker publication grants no authority to commit or push application code.
